# rpo-analytics

SQLite-backed ingestion and analytics for **synthetic** data-protection run
history: RPO compliance, drift detection, rolling trends and a transparent
capacity forecast, with a small CLI and CSV/JSON export.

> Unofficial, clean-room project. Not affiliated with any vendor. All data is
> generated by a seeded script; the API contract is invented. See
> [PROVENANCE.md](PROVENANCE.md) and [NOTICE](NOTICE).

## Quick start

```bash
python -m pip install -e ".[dev]"

rpo-analytics generate --seed 7 --days 45 --output sample.json
rpo-analytics --db rpo.db init            # create / migrate the schema
rpo-analytics --db rpo.db ingest sample.json
rpo-analytics --db rpo.db ingest sample.json   # idempotent: all duplicates

rpo-analytics --db rpo.db compliance --tz America/New_York
rpo-analytics --db rpo.db compliance --daily --format csv --output daily.csv
rpo-analytics --db rpo.db drift --fail-on-alert      # exit 2 if actionable alerts
rpo-analytics --db rpo.db trend --object vm-001 --rolling 7 --format json
rpo-analytics --db rpo.db forecast --capacity-limit-bytes 2000000000000
rpo-analytics --db rpo.db export-runs --format csv
```

Report commands take `--days` (default 30), `--end` (default: newest run),
`--tz` (IANA zone for day buckets, default `UTC`), `--format table|json|csv`
and `--output FILE`. Only `init` and `ingest` open the database for writing (and create it
if missing). Every report and export command (`compliance`, `drift`, `trend`, `forecast`,
`export-runs`) opens it read-only (SQLite `mode=ro` plus `query_only`), so a mistyped `--db`
path is an error and never creates an empty database. Run `init` first.

**Time zones.** `UTC` (the default) works with no timezone database at all. Other zones such
as `America/New_York` need the operating system's tz database or the `tzdata` package;
`tzdata` is installed automatically on Windows, and elsewhere via `pip install
'rpo-analytics[tz]'` if your system lacks one.

## Input contract (`rpo-analytics/1`)

```json
{
  "format": "rpo-analytics/1",
  "policies": [{"policy_key": "gold", "rpo_minutes": 60}],
  "runs": [{
    "run_id": "run-vm-001-000001", "workload_id": "vm-001", "policy_key": "gold",
    "started_at": "2026-01-01T00:00:00Z", "ended_at": "2026-01-01T00:05:00Z",
    "status": "success", "source_bytes": 100000000000, "written_bytes": 200000000
  }]
}
```

- Timestamps need an offset or `Z`; they are stored as UTC at 1 s resolution.
- `status` is `success`, `warning` or `failed`.
- **Idempotent ingest:** a `run_id` seen again with identical content is a
  duplicate (no-op); with different content it is a *conflict* (reported, the
  stored row is kept). Invalid records are rejected individually and listed.
  The CLI exits 1 if anything was rejected or conflicted.

## Definitions

| Term | Meaning |
| --- | --- |
| Recovery point | A run with status `success` or `warning`, timed at `ended_at`. |
| Object RPO | `rpo_minutes` of the policy on the object's most recent run. |
| Violation | Between recovery points `a` and `b` with `b - a > RPO`, the interval `[a + RPO, b)` is non-compliant. The window end closes the last gap. |
| Compliance ratio | `1 - violation_seconds / observed_seconds`. An object first seen mid-window is only measured from its first run. |
| Daily figures | Attributed to the local day (`--tz`) of `ended_at`; DST days are 23 or 25 hours and violations spanning midnight are split. |
| Rolling trend | Trailing N-day window: success rate is pooled (`recovery points / runs`), gap is the mean of daily max gaps. Days with no runs are marked `missing` and contribute nothing. |
| Drift | Compares the first `--baseline-days` (14) with the last `--recent-days` (7) of the window. Alerts: `rpo_drift` (mean daily max gap up by more than `--gap-increase-pct`, 25%; *critical* when the recent gap exceeds the RPO), `success_rate_drop` (15+ points), `no_recent_data`, and `insufficient_history` (info). |
| Capacity forecast | Ordinary least squares on cumulative stored bytes per day: `slope = Σ(x-x̄)(y-ȳ) / Σ(x-x̄)²`. `days_until_full = (capacity - last_bytes) / slope`. It reports `r_squared` so you can judge the fit. It ignores retention, expiry, dedupe changes and seasonality; it is a straight line, not machine learning. |

## Schema versioning

The version lives in `PRAGMA user_version`. Migrations are forward-only,
each runs in a transaction together with its version bump (a failure leaves
the previous version intact), re-running is a no-op, and a database newer than
the tool is refused.

| Version | Change |
| --- | --- |
| 1 | `policies`, `runs` |
| 2 | `runs.written_bytes` (default 0) |
| 3 | index on `runs(workload_id, ended_at)` |

## Related projects

`rpo-analytics` is one of five independent, synthetic-data projects that together sketch a small
data-protection toolkit: simulate a platform, collect from it, monitor it, analyse history and
check policy. They are **separate packages with separate, invented contracts**; none imports
another and none depends on another at install time.

| Project | Role |
|---|---|
| [protectionsim](https://github.com/greysave/protectionsim) | Deterministic local HTTP simulator of a synthetic data-protection API. |
| [backup-fleet-async](https://github.com/greysave/backup-fleet-async) | Asyncio collector that polls job status from many clusters into JSONL. |
| [protectionwatch](https://github.com/greysave/protectionwatch) | Prometheus-format monitor and terminal dashboard over an abstract fleet client. |
| [protection-policy-check](https://github.com/greysave/protection-policy-check) | Policy-as-code evaluator for job inventories, with a CI exit code. |

Ingests its own `rpo-analytics/1` JSON document. Feeding it from `protectionsim` runs or `backup-fleet-async` output would need a converter that does not exist yet.

## Development

```bash
python -m pip install -e ".[dev]"
ruff format --check . && ruff check .
mypy                       # strict
python -m compileall -q src tests
pytest --cov=rpo_analytics
```

The generator embeds two scenarios (a slowing `silver` object and a `bronze`
outage) plus random failures, so a default dataset produces violations and
drift alerts by design.
